# Feature Specification: 认证策略管理

**Feature Branch**: `001-auth-policy-management`

**Created**: 2026-09-05

**Status**: Draft

**Input**: User description: "这个fastarch是一个基础组件的项目服务包，当前已经实现iam的部分功能"。经确认，本特性为**认证策略管理**：为前端已存在的认证策略管理页面（策略列表 / 创建 / 编辑）补齐对应的契约定义与后端能力。

---

## 背景与现状

系统当前的认证方式只有密码登录。前端已提供"认证策略管理"页面（按 单点登录 SSO / 多重身份认证 MFA / 一次性密码认证 OTP 三类分页签管理策略），但页面数据全部为本地模拟，系统中不存在对应的契约（协议定义）与后端能力。本特性使认证策略成为真实可管理的数据，为后续认证流程按策略执行打下基础。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看认证策略列表 (Priority: P1)

租户管理员打开"认证策略管理"页面，按页签切换策略类型（单点登录 / 多重身份认证 / 一次性密码认证），看到该类型下所有已配置的策略（名称、描述、实现方式标识），页面数据来自系统真实存储。

**Why this priority**: 列表是管理能力的入口与基础；没有真实数据展示，后续任何管理操作都无从验证。

**Independent Test**: 预置若干不同类型的策略数据后打开列表页，三类页签各自展示对应类型且仅展示对应类型的策略，即为通过。

**Acceptance Scenarios**:

1. **Given** 系统中存在 2 条 SSO 类型的策略和 1 条 MFA 类型的策略，**When** 管理员打开策略列表并停留在"单点登录认证"页签，**Then** 仅展示那 2 条 SSO 策略，且名称、描述、实现方式标识与存储内容一致
2. **Given** 系统中存在策略数据，**When** 管理员切换到"多重身份认证"页签，**Then** 仅展示 MFA 类型策略，无需刷新整页
3. **Given** 某策略类型下没有策略，**When** 管理员切换到该页签，**Then** 展示空列表状态（而非报错或残留其他类型数据）

---

### User Story 2 - 创建认证策略 (Priority: P2)

管理员在某一策略类型页签下点击"新增"，填写策略名称、策略描述、实现方式标识后保存，新策略以该页签对应的类型持久化，并出现在列表中。

**Why this priority**: 有了数据展示后，创建是让策略数据从无到有的核心操作。

**Independent Test**: 在任一类型页签下通过创建表单提交一条完整策略，重新打开列表能看到该策略，即为通过。

**Acceptance Scenarios**:

1. **Given** 管理员在"一次性密码认证"页签，**When** 填写必填项（名称、描述、实现方式标识）并保存，**Then** 系统创建一条 OTP 类型策略，返回列表页可见该策略
2. **Given** 创建表单中任一必填项为空，**When** 管理员提交，**Then** 系统拒绝创建并明确提示缺失字段，不产生任何数据
3. **Given** 已存在同名策略，**When** 管理员以相同名称再次创建（同一策略类型下），**Then** 系统拒绝并提示名称重复

---

### User Story 3 - 编辑认证策略 (Priority: P3)

管理员在列表中对某条策略点击"编辑"，修改名称、描述或实现方式标识并保存，列表与后续查看展示的是更新后的内容。

**Why this priority**: 数据会随环境变化（如更换实现方式），编辑保证策略信息长期有效。

**Independent Test**: 修改一条已有策略的描述并保存，重新打开列表确认描述已更新，即为通过。

**Acceptance Scenarios**:

1. **Given** 存在一条策略，**When** 管理员修改其描述并保存，**Then** 保存成功且列表中该策略展示新描述
2. **Given** 编辑表单被清空了必填项，**When** 管理员提交，**Then** 系统拒绝保存且原数据保持不变
3. **Given** 管理员 A 打开编辑页期间管理员 B 已删除该策略，**When** A 提交修改，**Then** 系统提示策略已不存在，不产生脏数据

---

### User Story 4 - 删除认证策略 (Priority: P4)

管理员在列表中对某条策略点击"删除"，系统弹出确认框；确认后该策略不再出现在列表中。

**Why this priority**: 清理不再使用的策略，属于完整管理闭环的一部分，但优先级低于让策略可管理。

**Independent Test**: 删除一条已有策略并确认，重新打开列表该策略不再出现，即为通过。

**Acceptance Scenarios**:

1. **Given** 存在一条策略，**When** 管理员点击删除并在确认框中确认，**Then** 该策略从列表移除，刷新后依然不存在
2. **Given** 删除确认框弹出，**When** 管理员取消，**Then** 策略保持不变
3. **Given** 管理员 A、B 同时查看列表，**When** A 删除某策略成功后 B 再次删除同一条，**Then** B 收到"策略不存在"的明确提示，而非静默成功或系统错误

---

### Edge Cases

- 当策略类型参数不合法（如直接访问 URL 携带未知类型）时，系统提示"无效的认证策略类型"并回到列表页
- 当名称、描述超出长度限制时，系统在提交前给出校验提示
- 当并发编辑同一条策略时，后保存的一方不得覆盖先保存方的修改而不留痕迹（需给出冲突提示或以可追溯的方式处理）
- 当后端不可用或请求失败时，页面展示明确的失败提示，不得静默失败或展示模拟数据冒充真实数据

## Requirements *(mandatory)*

### Functional Requirements

- **FR-1**: 系统 MUST 支持三种认证策略类型：单点登录认证（SSO）、多重身份认证（MFA）、一次性密码认证（OTP）
- **FR-2**: 系统 MUST 支持按策略类型查询该类型下的全部策略列表，列表项至少包含：名称、描述、实现方式标识、唯一标识
- **FR-3**: 系统 MUST 支持在指定策略类型下创建策略，创建时 MUST 提供名称、描述、实现方式标识
- **FR-4**: 系统 MUST 拒绝同一策略类型下重名的策略创建
- **FR-5**: 系统 MUST 支持修改既有策略的名称、描述、实现方式标识；策略类型创建后不可变更
- **FR-6**: 系统 MUST 支持删除策略，且删除前 MUST 有明确的二次确认
- **FR-7**: 系统 MUST 对名称与描述实施长度约束，并在提交前完成校验
- **FR-8**: 系统 MUST 保证列表、创建、编辑、删除结果即时反映在后续查询中（不展示过期缓存数据）
- **FR-9**: 系统 MUST 对策略的所有变更操作做身份与权限控制——仅具备相应管理权限的账号可执行
- **FR-10**: 所有操作失败时系统 MUST 返回用户可理解的错误信息，不得静默失败

*范围边界：本特性仅覆盖策略定义的管理（CRUD）。策略在登录/认证流程中的实际执行（如登录时按策略要求二次验证）不属于本特性，将在后续特性中定义。*

### Key Entities *(include if feature involves data)*

- **认证策略（Authentication Policy）**: 一条可管理的认证策略定义。关键属性：唯一标识、策略类型（SSO/MFA/OTP 三选一）、策略名称（同类型下唯一）、描述、实现方式标识（指向该策略对接的具体认证实现）。策略类型一经创建不可变更。
- **策略类型（Policy Type）**: 策略的分类维度，当前为固定三种（SSO、MFA、OTP），决定列表页签与创建入口的归属。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员能在 1 分钟内完成一条策略的创建并在列表中看到它
- **SC-002**: 策略列表页首屏在 2 秒内完成加载并展示真实数据（预置 100 条以内策略时）
- **SC-003**: 全部页面展示的数据 100% 来源于系统真实存储，无任何本地模拟数据
- **SC-004**: 90% 的管理员在无帮助文档情况下，首次即可正确完成"创建—查看—编辑—删除"完整流程
- **SC-005**: 所有失败操作（校验失败、重名、并发冲突、权限不足）均向用户给出明确、可理解的提示

## Assumptions

- 本特性范围限定为策略**定义的管理**；策略在认证流程中的**执行与生效**由后续特性承接
- 三种策略类型（SSO/MFA/OTP）为当前固定集合，与现有前端页面保持一致；未来如需扩展类型，另行立项
- "实现方式标识"在本特性中仅作为策略指向具体实现的引用信息保存与展示，其指向对象的注册与校验不在本特性范围内
- 操作者身份沿用系统现有的登录与权限体系（与账号/授权管理一致），不新建独立的权限模型
- 数据规模预期为管理配置类低频数据（单类型百条以内），性能目标按此量级设定

## Dependencies

- 依赖系统现有的账号登录能力（管理操作需已登录且具备管理权限）
- 前端认证策略管理页面已存在（列表 / 创建 / 编辑 / 删除入口齐全），本特性为其接入真实数据与能力
