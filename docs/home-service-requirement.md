# 企业首页展示后台 · 需求规格（requirement_spec）

## 1. 背景与目标

企业官网首页目前是写死在代码里的静态内容，运营每次改一句文案、调一次区块顺序都要找开发改代码并发版。目标是把「首页内容 + 布局」变成可配置数据：运营在企业官网控制台里编辑，右侧实时预览，保存草稿后发布，线上首页读取已发布版本渲染。

**本期边界**：单站点、单首页、单语言；不做多页 CMS、素材库上传、多语言、审批流、定时发布。

## 2. 角色与场景

| 角色 | 场景 |
| --- | --- |
| 运营 / 市场 | 修改品牌名、首屏文案、按钮文案、主题色、区块内容与顺序，边改边看效果 |
| 站点负责人 | 确认预览效果后发布；发布前可随时保存草稿，不影响线上 |
| 开发 / 测试 / 运维 | 验证接口、权限、草稿与发布态隔离、发布后可读取 |

## 3. 功能需求

- **FR-1 独立控制台**：新增「企业官网」控制台，仅对已接入 `home` 应用的用户可见；与其他控制台共用统一登录。
- **FR-2 单首页配置**：每个应用只有一份首页配置，包含品牌信息、首屏、导航、主题、区块列表。
- **FR-3 文案可编辑**：品牌名、Logo 文字、首屏眉标/主标题/副标题、主次按钮文案、每个区块的标题与正文均可编辑。
- **FR-4 布局可调整**：支持整页布局（经典左文右图 / 居中 / 分栏）切换；支持区块顺序上移/下移、显示/隐藏、单区块布局（居中 / 左对齐 / 卡片组）。
- **FR-5 实时预览**：编辑区任意字段变化，右侧预览立即更新，不需要先保存；支持全屏预览。
- **FR-6 草稿与发布分离**：保存只写草稿；发布把当前草稿复制为已发布版本并记录发布时间/版本；线上读取已发布版本，不受草稿影响。
- **FR-7 版本并发保护**：保存时携带当前版本号，服务端版本不一致返回业务冲突码，前端提示刷新，避免多人覆盖。
- **FR-8 默认内容**：首次访问没有配置时返回内置默认首页，页面可直接编辑并保存，不出现空白。

## 4. 非功能需求

- **权限**：读取/保存/发布分别由 `home.page.get`、`home.page.update`、`home.page.publish` 控制；未登记方法 fail-closed。
- **数据归属**：配置按 `application_id = 4（home）` 隔离，接口只读写当前应用的数据。
- **审计**：记录创建人/更新人、创建/更新时间；发布单独记录发布时间与发布版本。
- **容量**：单份首页 JSON ≤ 200KB；服务端校验必须是合法 JSON 对象。
- **安全**：不允许前端直接拼 SQL/文件路径；所有接口经 proto 契约 + 网关 + IAM 判权。

## 5. 验收标准

- **AC-1** 用户登录后能在控制台选择页看到「企业官网」，进入后侧栏出现「首页配置」。
- **AC-2** 打开首页配置页能看到默认内容与右侧预览，修改任一文案预览即时变化。
- **AC-3** 修改主题色、整页布局、区块顺序/显隐/单区块布局，预览结构与样式同步变化。
- **AC-4** 点击「保存草稿」后刷新页面，草稿内容仍在；已发布内容不变。
- **AC-5** 点击「发布」后，已发布版本等于当前草稿，发布时间更新；再次修改草稿不影响已发布版本。
- **AC-6** 两个页面同时编辑时，旧版本保存返回冲突提示，不静默覆盖。
- **AC-7** 未持有对应权限码的账号调用保存/发布接口返回 403；未登录返回 401。
- **AC-8** 后端 `go test ./...`、前端 `pnpm build` 通过；服务启动迁移成功，接口可读写。

## 6. 不在本期范围

多首页/多站点、图片与视频上传、多语言、SEO 元数据管理、定时发布、审批流、页面模板市场。
